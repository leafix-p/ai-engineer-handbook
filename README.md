## 这套手册适合谁

- 想转行或入门 AI 工程师，但不知道先学什么、后学什么的人；
- 会调 Python、会跑 demo，但缺少完整知识体系的人；
- 做嵌入式 / 驱动 / 硬件，想补齐 AI 模型与部署能力的工程师；
- 需要给项目做端侧 AI 选型（芯片、框架、模型）的技术负责人。

阅读前不需要精通数学，但需要会 Python 基础语法，并愿意动手跑代码。

## 三条学习主线

| 主线 | 核心问题 | 典型岗位 | 建议重点章节 |
|---|---|---|---|
| 视觉 | 如何让机器看懂图像/视频 | CV 算法、智能相机、工业质检、机器人感知 | 03–05、10–13 |
| LLM | 如何让模型理解并生成语言、调用工具 | LLM 应用、Agent、RAG、模型部署 | 06–08、10–13 |
| 语音 | 如何让机器听懂并开口说话 | ASR/TTS、语音助手、智能硬件 | 09–13 |

三条线共享第 01–02 章的基础，最终都会汇入第 10–14 章的工程与落地。不要一开始就同时学三条线；先选一条主线打通「训练 → 导出 → 部署 → 评测」的完整闭环，再横向扩展。

## 如何使用

1. **先读 [00 导读](00-导读与学习路线.md)**，按自己的背景选一条路线和一份时间表。
2. **每章按「概念 → 代码/命令 → 检查题」的顺序学**。只看不跑，等于没学。
3. **每学完一个模块，做一个小项目**，例如：训练一个 YOLO 检测器并用 ONNX 导出；用 llama.cpp 在本机跑一个 4B 模型；用 FunASR 做一个离线字幕工具。
4. **选型时读第 11–13 章**，重点看「工具链成熟度、算子支持、量化精度、功耗、供货周期」，不要只看 TOPS。
5. **数据版本提醒**：模型版本、芯片参数、SDK 名称迭代很快。手册中的具体数字用于建立量级概念，实际项目务必以厂商最新官方文档和实测为准。
6. **想在 iPhone 上随时读**：看 [第 15 章](15-在线笔记与移动学习方案.md)，推荐 Git + Docsify/MkDocs + GitHub Pages，手机 Safari 添加到主屏幕。

## 本手册的几条判断原则

- **TOPS 不等于可用算力**：还要看量化方式（INT8/FP16/FP4）、稀疏标注、内存带宽、算子覆盖和实际吞吐。
- **精度不等于准确率**：量化后必须在自己的数据集上复测，不能只看 ImageNet 或厂商跑分。
- **端侧的第一瓶颈通常是内存带宽和散热**，不是峰值算力。
- **软件生态决定落地成本**：同样的 TOPS，工具链成熟度可能带来数倍的人力和周期差异。
- **先闭环，再优化**：先跑通「数据 → 训练 → 导出 → 板端推理 → 评测」，再谈剪枝、蒸馏、算子融合。
